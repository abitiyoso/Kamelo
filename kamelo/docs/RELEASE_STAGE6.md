## Recovery result and evidence quality

`scripts/release-restore-drill.mjs` refuses any source except the named disposable loopback QA database. It creates a new private cluster on port 55433 with UTF-8/C locale and SCRAM authentication, never reusing/resetting a database or stopping an unrelated process. A repeatable-read exported snapshot supplies both a PostgreSQL custom-format dump and the source table hashes. A single-transaction restore remaps ownership/ACLs to a disposable role. PostgreSQL 18.6 client tools came from the [official EDB portable binaries page](https://www.enterprisedb.com/download-postgresql-binaries); the local embedded server remains 18.4. Tool ZIP SHA-256: `e2246ba91d22345bc3d017586c09ede52d9df180b1eeb480f050445f1cad84e2` (locally measured download fingerprint, not a vendor-signed checksum).

The WIN1252 source was dumped with UTF-8 output and restored to UTF-8. Every public table's count and canonical row hash, including the 22 migration records, matched. Constraints, indexes, non-internal triggers and public functions matched; PostgreSQL's canonical pretty format avoids treating redundant AND parentheses as different CHECK rules. A non-Latin/emoji value round-tripped through a real organization field on the restored copy and was restored to its original value. The source table hashes were unchanged by the drill. See [`restore.json`](../artifacts/release-stage6/restore.json).

Dump creation plus source hashing took 3,453 ms; restore took 2,577 ms; the complete successful local drill took 22,009 ms. The custom dump is 15,346,945 bytes. These measurements are for synthetic local data. Production backup scheduling, encryption, monitoring, RPO/RTO, real data scale, roles/ACLs, extension ownership and deployment recovery are not established by this result. The procedure follows PostgreSQL's documented [dump encoding and custom format](https://www.postgresql.org/docs/18/app-pgdump.html) and [transactional restore](https://www.postgresql.org/docs/18/app-pgrestore.html) options.

All 645 available private files were copied and verified byte-for-byte. Of 777 proof records, 407 real upload records matched their stored SHA-256 and file size. Earlier QA suites intentionally created 170 metadata-only `QUEUE-HISTORY-*` / `REMINDER-PENDING` placeholders and 200 `HISTORY-n` copied files with synthetic hash formulas. The drill requires those exact fixture signatures, preserves them unchanged and reports them separately; it does not repair, invent or discard evidence. No additional file became missing or changed during recovery. **These exceptions are only for this disposable fixture database and must never be accepted for production evidence.** Existing genuine evidence mismatches would fail the drill. All 54 financial-document snapshots decrypted with the protected matching key and passed their internal snapshot checksum.

The dump, cluster files, database password, copied encryption key, fixture credentials and proof bytes stay under ignored `.local-secrets/release-stage6/`. None enters the review checkout, Git or deliverable ZIP. Public evidence contains counts, hashes, timings and synthetic UI screenshots, not keys or uploaded documents.

## Reproduce the named local rehearsal

Use the same private QA key and existing disposable database, with the approved stage 5 build present. Install compatible official PostgreSQL client utilities privately and set `PGTOOLS_BIN` if they are not at the launcher's default private location. Never pass a production URL. The launcher asserts the source database/port, refuses an occupied restore port, creates a new cluster directory and never deletes a prior drill.

1. Run `pnpm qa:restore` with `DATABASE_URL` set to the named disposable QA database on 55432. The protected `current.json` points to that successful recovery copy and its compatible key/files.
2. Run `node scripts/release-restore-preview.mjs`. It checks the destination DB identity, listens on loopback 3002 and explicitly disables transactional email and recipient/provider credentials. No worker is started. Current IoT remains MOCK-only and LEO remains rule-based.
3. Run `pnpm test:recovery`. Private fixture identities captured with the dump are used; this does not register new users or send verification emails. Only restored-copy sessions/rate buckets and a temporarily revoked/restored test grant are changed. Business/outbox hashes must remain identical.
4. Run `pnpm test:release` with QA `DATABASE_URL`, `TEST_URL=http://127.0.0.1:3001` and the private QA keys. These existing suites intentionally add synthetic data to the original disposable QA database; they do not target the restored copy or production.
5. After inspection, stop only the recovery preview's verified processes and use native `pg_ctl -D <current recovery data directory> -m fast -w stop`. Resolve/check that directory stays under `.local-secrets/release-stage6/` first. The successful recovery copy is currently retained for review; no database or backup is deleted by these scripts.
